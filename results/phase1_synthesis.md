   - Planned role: primary novelty path for Phase 3 and Phase 4.

2. `constraint_projected_kepler -> resolution_coupled_softening -> neighbor_tree_gravity`
   - Why it survives: it reframes numerical hacks as representational honesty controls, which is compatible with the H1 claim even if the force engine stays small.
   - Planned role: secondary novelty path for stabilization and audit reporting.

3. `neighbor_tree_gravity -> event_sparse_far_field -> epicycle_patch_streaming -> resolution_coupled_softening`
   - Why it survives: it offers a credible future branch for scaling small scenes without abandoning local exactness.
   - Planned role: exploratory path only if the audit-first kernel is already stable and time remains.

## Rejected Branches

1. `epicycle_patch_streaming` as the main thesis.
   - Rejection reason: too ring-specific and too close to a game-engine streaming architecture claim, which weakens the deterministic reference-kernel story.

2. `trajectory_mass_inference` as the first research deliverable.
   - Rejection reason: it depends on a trustworthy forward simulator and would turn novelty into an interface affordance before the physics audit exists.

3. `neighbor_tree_gravity + event_sparse_far_field` as the initial implementation center.
   - Rejection reason: the performance branch is interesting, but it risks drifting into crowded large-N optimization territory before the small-N audit obligations are met.

- `H2` backup: activate only if close-encounter evidence shows the deterministic audit wedge is too brittle.
- `H3` hold: implement unit-safe ideas opportunistically inside scenario IO and reporting, but do not promote them above H1 in Phase 1.
