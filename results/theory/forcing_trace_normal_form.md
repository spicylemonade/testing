# Forcing Trace Normal Form

## Exact trace engine

We use the exact verifier implemented in `tools/kakeya_ca_exact.py` as a trace
engine rather than as a yes/no checker.  For a witness `(X,G,R,T)` with vertex
set `V`, let `F_0 := T`.  Given `F_k`, we quotient out the coordinates of the
already forced vertices and compute the exact rational span of:

- all singleton seed generators from `R`;
- all edge-difference generators induced by the labeled edges of `G`.

A vertex `v` enters `F_{k+1}` iff the diagonal target `(1,-1)` supported at `v`
lies in that quotient span.  The **synchronous forcing trace normal form** is
the layered derivation object

`NF(X,G,R,T) := (F_0, Delta_0, F_1, Delta_1, ...)`

where `Delta_k = F_{k+1} \ F_k` and each newly forced vertex carries the
lexicographically canonical support returned by the fixed Gaussian-elimination
order used in the trace engine.

This normal form is deterministic: once the generator ordering is fixed, every
witness has exactly one layered quotient-span closure trace.  The only
symmetries we quotient by below are the obvious row and column flips of the
`2x2` product grid.

## Study regime

The machine-readable corpus lives under `results/theory/forcing_traces/`.

The exhaustive tiny regime is:

- `dims = [2,2]`;
- full support on all three edge slots;
- label palette
  `[(1,0),(0,1),(1,1),(1,2)]`;
- no initial `T`;
- up to three distinct seed atoms `(vertex,label)`.

The corpus was generated by `tools/kakeya_trace_corpus.py`, which checked all
`44,608` witnesses in this regime and emitted every exact-valid class as a JSON
trace artifact.

## Exhaustive findings

The summary file
`results/theory/forcing_traces/tiny_2x2_full_seeds_le3/corpus_summary.json`
records the following exact facts:

- `44,608` raw witnesses were checked.
- Exactly `48` witnesses are exact-valid.
- Every exact-valid witness has score `7/4`.
- Every exact-valid witness has the same layered trace skeleton up to which
  corner nucleates first:
  one corner is forced in layer `0`, and the remaining three vertices are
  forced in layer `1`.

Equivalently, in this regime there are no exact-valid traces of the forms:

- two vertices in the first nontrivial layer;
- a three-layer cascade;
- any score below `7/4`.

Thus the warm-up gadget is rigid in a stronger sense than the public benchmark
discussion suggests: within the audited `2x2` regime there is no alternative
micro-witness topology hiding behind different labels or seed placements.

## Structural law

The local strip tables

- `results/theory/forcing_traces/local_strip_states/width2_one_sided.json`
- `results/theory/forcing_traces/local_strip_states/width3_one_sided.json`

exhaustively check every one-sided local activation pattern over the same label
palette for fresh `2x1` and `3x1` columns.  In both widths the strict
improvement count is `0`.

Interpretation:

- A fresh width-`2` column cannot gain a newly forced row from row-singleton
  input arriving from only one side.
- A fresh width-`3` column also cannot gain a newly forced row from only one
  side over this audited palette.

This yields the first concrete obstruction used in the later search:

> Any proof-carrying CA that beats the warm-up by strip propagation cannot be a
> unilateral left-to-right wave in widths `2` or `3`; it must use either
> two-sided coupling, internal seeds inside the target block, or a wider
> macrocell.

This obstruction is stronger than generic depth or degree heuristics because it
is computed from the exact quotient-span closure rule itself.

## Consequence for search

The exact-valid `2x2` corpus and the one-sided strip tables together narrow the
CA search space substantially:

- width `2` is not a plausible self-sustaining lane below the target score;
- width `3` remains viable only in a coupled or multi-boundary regime;
- future search should prioritize coupled strip states, macrocells, or other
  genuinely two-sided constructions rather than unilateral growth heuristics.
