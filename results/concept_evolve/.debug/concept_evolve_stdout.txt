It computes `gcd(u, v)` by repeatedly applying four identities:\n\n1. **Base case**: `gcd(u, 0) = u` and `gcd(0, v) = v`\n2. **Both even**: `gcd(2u, 2v) = 2 * gcd(u, v)`\n3. **Mixed parity**: `gcd(2u, v) = gcd(u, v)` when `v` is odd (and symmetrically)\n4. **Both odd**: `gcd(u, v) = gcd(|u - v|, min(u, v))` when both are odd\n\nThe key advantage over the Euclidean algorithm is that it replaces division (the `idiv` instruction on x86, which takes 20-90+ cycles depending on operand size) with shifts, subtractions, and comparisons (each typically 1 cycle).\n\nThe naive recursive implementation is slow because it has many branches:\n\n```c\nint gcd(int a, int b) {\n    if (a == 0) return b;\n    if (b == 0) return a;\n    if (a == b) return a;\n    if (a % 2 == 0) {\n        if (b % 2 == 0) return 2 * gcd(a / 2, b / 2);\n        else return gcd(a / 2, b);\n    } else {\n        if (b % 2 == 0) return gcd(a, b / 2);\n        else return gcd(abs(a - b), min(a, b));\n    }\n}\n```\n\nBenchmarks from Algorithmica show this is roughly 2x *slower* than `std::gcd` due to all the branching overhead.\n\n#### 1.2 Three Key Optimizations to Make It Branchless\n\n**Optimization 1: Replace trial division by 2 with CTZ + single shift.**\nInstead of repeatedly dividing by 2 in a loop, use `__builtin_ctz()` (which compiles to `tzcnt` or `bsf` on x86) to find the exact number of trailing zeros, then shift once.
