**Summary of the probe:**

The core bottleneck is that Python's interpreted, object-heavy execution model catastrophically amplifies the constant-factor overhead of tree traversal (pointer chasing, recursive dispatch, branch-dependent control flow), while simultaneously being well-suited to vectorized brute-force computation via NumPy. This creates a crossover point (~10^4 particles in Python vs ~100 in C) where the O(N^2) method beats O(N log N).

**Key findings from research:**
- **pytreegrav** solves this via numba jitclass octrees, achieving near-C tree walk performance
- **Morton-code implicit octrees** eliminate the tree data structure entirely, replacing it with sorted arrays
- **Traversal splicing** (Purdue, PACT 2013) batches similar tree walks for SIMD execution
- **GNN surrogates** (AAAI 2021) replace tree traversal with fixed-depth vectorizable message passing
- **Dual-tree GPU decomposition** separates serial walk (CPU) from parallel force computation (GPU)

3. FlashAttention-inspired tiled brute-force for moderate N (extends the vectorized regime)
