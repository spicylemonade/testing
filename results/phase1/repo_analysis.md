## 2. Modules in `.archivara/`

### 2.1 `concept_evolve.py` (604 lines)
**Purpose:** Cross-domain concept tree generation and traversal backed by OpenCode sub-agents.

**Commands:**
- `evolve <topic>`: Generates concept cards, semantic bridge graph, introspection data, and steering directions. Uses a sub-agent to produce JSON-structured concept exploration. Caches results with configurable TTL (default 7200s). Creates materialized concept folders in `results/concept_evolve/tree/`.
- `probe <problem>`: Deep concept probing for specific bottlenecks. Produces forced bridges, anomaly results, and steering directions. Output: `results/concept_evolve/probe_result.json`.
- `reframe <problem>`: Reframes a problem in at least 8 distinct domains. Output: `results/concept_evolve/reframings.json`.
- `walk [--seed SEED] [--depth DEPTH]`: Traverses the concept tree walk paths generated by evolve. Filters by seed concept and depth. Output: `results/concept_evolve/walk_session.json`.

**Key implementation details:**
- Uses `opencode run --agent build --model anthropic/claude-opus-4-6 --format json` for sub-agent calls
- Implements file locking to prevent concurrent evolve runs
- Semantic Scholar integration for literature discovery per concept
- Walk paths use DFS with configurable depth (max 8) and width (max 4)
- JSON extraction from potentially noisy LLM output using multiple strategies

### 2.2 `semantic_scholar.py` (277 lines)
**Purpose:** Robust Semantic Scholar API wrapper for literature graph traversal.

**Commands:**
- `search <query> [--limit N] [--json] [--save PATH]`: Full-text search with structured results
- `citations <paperId> [--limit N]`: Get papers citing a given paper
- `references <paperId> [--limit N]`: Get papers referenced by a given paper
- `recommend <paperId1> [<paperId2>...]`: Paper recommendations via Semantic Scholar API
- `graph <query> [--roots N] [--fanout N]`: Build citation graph from seed query
- `bibtex <paperId>`: Generate BibTeX entry for a paper

**Key implementation details:**
- Exponential backoff retry (6 attempts, max 8s delay)
- Fields retrieved: paperId, title, authors, year, citationCount, abstract, externalIds, venue, url
- Pretty-print and JSON output modes

### 2.3 `opencode.json` (88 lines)
**Purpose:** OpenCode configuration file defining model, agents, and permissions.

**Configuration:**
- Model: `anthropic/claude-opus-4-6`
- Default agent: `build`
- Provider: Anthropic with API key from environment
- Permissions: All tools allowed (edit, webfetch, websearch, bash, etc.)

**Agent roles:**
- `orchestrator`: Planning-only rubric author (no concept_evolve)
- `researcher`: Execution-heavy research worker (all tools including concept_evolve and semantic_scholar)
- `writer`: Paper writing and synthesis (semantic_scholar, no concept_evolve)
- `reviewer`: Peer review and quality control (semantic_scholar, no concept_evolve)
- `concept_worker`: ConceptEvolve sub-worker (no recursive concept tool, all other tools)

### 2.4 `logs/`
**Purpose:** Log storage directory for execution traces.

## 5. Semantic Scholar API Capabilities

The Semantic Scholar integration provides:

1. **Paper search**: Full-text query with configurable result limit (default 10)
2. **Citation traversal**: Forward (who cites this paper) and backward (what does this paper cite)
3. **Recommendations**: Given seed papers, find related work
4. **Citation graph construction**: Multi-hop graph from seed query with configurable roots and fanout
5. **BibTeX export**: Auto-generate BibTeX entries for any paper ID

**Fields available per paper:**
- paperId, title, year, citationCount
- authors (list of names)
- venue, abstract
- externalIds (DOI, ArXiv, MAG, etc.)
- url (Semantic Scholar permalink)

**Limitations observed:**
- Some queries fail with connection errors (transient)
- Rate limiting requires the built-in exponential backoff
- Abstract may be null for older papers
- Some paper IDs return null entries in citation/reference lists

## 8. Key Observations for Research Strategy

1. **Sub-agent reliability**: The ConceptEvolve sub-agent may fail to produce parseable JSON output. Manual population of concept artifacts is a reliable fallback.

2. **Semantic Scholar coverage**: The API has good coverage for Bloch constant literature but struggles with highly specialized queries (e.g., "Bonk distortion theorem" fails).

3. **Tool separation**: The architecture separates discovery (literature-graph-miner, concept-tree-explorer) from execution (researcher agent), enabling parallel exploration.

4. **Critical path**: The research flows from literature review → baseline reproduction → novel approaches → experimental verification → documentation. Phases 2-3 are the mathematical core.

5. **Verification strategy**: Every claimed bound should be independently verified (item_025). This requires implementing at least two independent computation methods for each result.

## 10. Known State of B_u Bounds

From literature survey:
- **Best lower bound**: B_u > 0.5708858 (Skinner 2009)
- **Best upper bound**: B_u ≤ 0.6564 (Carroll & Ortega-Cerda 2008, from harmonically symmetric slit domains)
- **Wikipedia reports**: 0.5 < A ≤ 0.7853 (where A is called the univalent Bloch constant)
  - Note: The 0.7853 may refer to an older or different definition. Carroll & Ortega-Cerda's 0.6564 appears to be tighter.
- **Trivial upper bound**: B_u ≤ 1 (identity function)
- **Chain relation**: B ≤ B_l ≤ L ≤ B_u, where B ≈ 0.4332+, L ≤ 0.5433

The gap between best known bounds is: 0.5708858 < B_u ≤ 0.6564
This represents an uncertainty interval of width approximately 0.0855.
