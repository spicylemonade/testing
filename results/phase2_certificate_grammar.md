# Phase 2 Certificate Grammar

## Purpose

Freeze one exact CA-to-certificate grammar before any search. Every candidate in the active `H1_macrocell_substitution` route must compile directly to a legal `(X; d_i; f_i; T; R)` instance with no bespoke global repair.

## Chosen Family: Corridor Substitution Automata

We use a thin corridor family with `k = 2`.

- `d_1 = H`, the fixed corridor height.
- `d_2 = W_\ell`, the width at substitution level `\ell`.
- `H` is small and fixed per experiment family, typically `2 <= H <= 4`.
- `W_\ell` is generated by a 1D substitution rule on column states.

The cellular automaton lives on the width axis only. It is a macrocell/substitution automaton, not a translation-invariant infinite CA.

## Fixed Descriptor

Each legal candidate family is a tuple

`F = (X, H, I, B, Sigma, sigma, nu, eta, rho, tau, beta)`

with the following components.

### 1. Label Alphabet `X`

- `X` is a finite subset of `Z^2`.
- `(0,0) in X`.
- If `x = (a,b) in X \\ {(0,0)}`, then `a + b != 0`.
- Nonzero labels in `X` are shared across all scales of the family.
- Scale-dependent growth of `X` is illegal for `H1`; that belongs only to matched controls or to a killed `H3` hedge.

### 2. Corridor Height `H`

- `H` is fixed before any search on a family.
- The extractor never changes `H` across substitution levels.
- `H` is part of the search budget and part of the matched baseline definition.

### 3. Interface Alphabet `I`

We freeze one finite interface alphabet

`I = {closed, carry_a, carry_b, gate}`.

Interpretation:

- `closed`: no compositional promise beyond admissible adjacency.
- `carry_a`, `carry_b`: abstract transport channels used by the local grammar to preserve two distinct boundary modes across substitution.
- `gate`: a boundary state allowed to inject or absorb a local forcing motif.

The interface alphabet is semantic only; it does not itself certify forcing.

### 4. Boundary Types `B`

We freeze one boundary alphabet

`B = {left, middle, right}`.

- `left` and `right` are permitted only on the outermost columns of the extracted corridor.
- `middle` is required on all internal columns.

### 5. Column State Alphabet `Sigma`

Each column state is a finite record

`s = (b, i_L, i_R, seed_tag, solved_tag)`

where

- `b in B`
- `i_L, i_R in I`
- `seed_tag in P^H`
- `solved_tag in {0,1}^H`

and `P = {0, p1, p2, p3, p4}` is a fixed finite seed-token alphabet.

Interpretation:

- `seed_tag[r] = pj` means that row `r` in that column emits one singleton seed labeled by the `j`-th nonzero token selected from `X`.
- `seed_tag[r] = 0` means no singleton seed at that vertex.
- `solved_tag[r] = 1` means the vertex is placed in the initial `T`.

The state alphabet is finite once `H` is fixed.

### 6. Local Seed Extractor `rho`

- `rho : Sigma -> P^H`
- `rho(s)` is exactly the `seed_tag` component of the state.
- No other function may inject singleton seeds.

### 7. Local Initial-Solved Extractor `tau`

- `tau : Sigma -> {0,1}^H`
- `tau(s)` is exactly the `solved_tag` component of the state.
- No other function may populate the initial `T`.

### 8. Boundary Condition `beta`

- `beta = (i_left^*, i_right^*)` is the pair of allowed outer interfaces.
- The leftmost column must satisfy `i_L = i_left^*`.
- The rightmost column must satisfy `i_R = i_right^*`.
- Candidates violating `beta` are rejected before extraction.

### 9. Active H1 Pilot Caps

For the active H1 pilot only:

- `|Sigma_active| <= 12`
- serialized grammar description length is logged and capped per benchmark row
- the cap is matched in the no-CA and randomization controls when a grammar-mediated family is compared against them

## Extraction Rules

Let the level-`ell` substitution word be `w_ell = s_1 ... s_W`.

### 1. Constructible Graph Data

- `d_1 = H`
- `d_2 = W`

### 2. Vertical Edge Dictionary `f_1`

The family contains one fixed vertical profile

`nu in (X union {(0,0)})^(H-1)`.

Extraction:

- `f_1(r) = nu_r` for every `1 <= r <= H-1`.

This means the vertical edges between rows `r` and `r+1` are constant across all columns.

### 3. Horizontal Edge Dictionary `f_2`

We freeze one local extractor

`eta : Sigma x Sigma -> (X union {(0,0)})^H`.

For each adjacent pair of columns `(s_c, s_{c+1})`,

- `f_2(r, c) = eta(s_c, s_{c+1})[r]`.

Legality condition:

- if `s_c.i_R != s_{c+1}.i_L`, then the pair is illegal and the candidate is rejected immediately;
- there is no repair step that inserts or edits edges after extraction.

### 4. Seed Set `R`

We fix a token-to-label map from `{p1, p2, p3, p4}` to distinct chosen nonzero elements of `X`.

For each column `c` and row `r`:

- if `seed_tag[r] = pj`, add one singleton-support element to `R` placing the corresponding label at vertex `[r, c]`;
- if `seed_tag[r] = 0`, add nothing.

Every element of `R` is therefore legal by construction: one nonzero `X` label on exactly one vertex.

### 5. Initial Solved Set `T`

For each column `c` and row `r`:

- if `solved_tag[r] = 1`, include `[r, c]` in `T`;
- otherwise do not.

## Substitution Rule

We freeze one width-expanding substitution

`sigma : Sigma -> Sigma^w`

with fixed small width `w in {2,3,4}`.

- Level `0` is a legal seed word `w_0`.
- Level `ell+1` is obtained by concatenating `sigma(s)` for each `s` in `w_ell`.
- The same `Sigma`, `eta`, `rho`, `tau`, `beta`, `nu`, and token map are used at every level.

Illegal for `H1`:

- level-specific lookup tables,
- level-specific state alphabets,
- level-specific repairs of mismatched interfaces,
- level-specific boundary conditions,
- any extraction step that inspects the whole word to modify a local decision.

## Exact Legality Checks

Every extracted candidate must pass all of the following before any score is computed.

### Operation 1 compatibility

- Each nonzero entry of `f_1` or `f_2` is an element of `X \\ {(0,0)}`.
- Edge relations are exactly those induced by the legal `f_i`; there are no extra relation generators.

### Operation 2 compatibility

- The compiler never marks a vertex as solved because a surrogate predicted it.
- A vertex enters `T` initially only through `solved_tag`, or later only through the exact verifier implementing operation 2.

### Operation 3 compatibility

- The search side may propose candidates, but only the exact verifier may take integer linear combinations.
- No CA state variable counts as a proof unless the exact verifier confirms the required support-clearing condition.

## Rejection Rules

Reject a route immediately if any of the following happens:

- the candidate needs a global clean-up pass to fix interface mismatches;
- the compiler needs scale-specific exceptions;
- `X` grows with scale in the active `H1` route;
- the extractor uses verifier feedback to rewrite `f_i`, `R`, or `T` after the candidate is built;
- a claimed score depends on surrogate occupancy, closure time, or another proxy rather than on the exact extracted `(m+r)/(n-t)`.

## Why This Grammar Is Acceptable

- It is local enough to justify a CA story.
- It is explicit enough to compile directly to legal verifier data.
- It supports level-1 versus level-2 transfer, aspect ratio controls, and stage-order perturbations.
- It blocks the main hidden-complexity failure mode identified by the director brief and falsifier: the compiler cannot smuggle in global repairs.
