# Prior Art Watchlist

## Live Mathematical Watchlist

These are the sources that now define the real overlap boundary for the project.

### 1. OEIS A129258
- Verdict: baseline provenance, not optional prior art.
- Relevance: defines the array, recurrence, and prime-separator framing.
- Differentiation note: reproducing the array or repeating the prime split is not novelty; the contribution must add validated witness-level mechanism or a proof-quality obstruction.

### 2. OEIS A129259
- Verdict: baseline provenance, not optional prior art.
- Relevance: defines the first row and is the closest public source for the bounded-difference question.
- Differentiation note: any serious note must treat the bounded-difference question and the row-level prime split as already public.

### 3. Clark Kimberling, *100 Conjectures and/or Problems*
- Verdict: baseline provenance for the open-problem statement.
- Relevance: the primary-source problem page states the bounded-difference question and points back to A129258/A129259.
- Differentiation note: restating Kimberling's problem with more data is not enough.

### 4. Kevin Ford, *The multiplication table problem*
- Verdict: highest live overlap risk.
- Relevance: any argument that appeals to local product coverage, dense distinct products, or restricted multiplication-table behavior must clear this source.
- Differentiation note: the work only survives if the mex-coupled endogenous border generation is mathematically essential.

### 5. Kevin Ford, *The distribution of integers with a divisor in a given interval*
- Verdict: highest live overlap risk.
- Relevance: the nearest divisor-in-an-interval source for local frontier coverage language.
- Differentiation note: frontier witnesses must do more than rename divisor-density phenomena.

### 6. Dimitrios Koukoulopoulos, *Generalized and restricted multiplication tables of integers*
- Verdict: medium overlap.
- Relevance: nearby restricted-product-set comparison point.
- Differentiation note: use as overlap control only; current metadata is secondary and should not be load-bearing.

### 7. Pach and S{\'a}ndor, *Multiplicative Bases and an Erd\H{o}s Problem*
- Verdict: medium overlap.
- Relevance: closest multiplicative-basis branch for the de-prioritized H3 framing.
- Differentiation note: if the project falls back to sparse multiplicative-basis language without a T-specific invariant, it will collapse into this branch.
