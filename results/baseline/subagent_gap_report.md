# Baseline Gap Report (Ranked for Credible Results)

Scope: synthesized from current baseline artifacts in `results/baseline/`, simulator/scripts in `src/gravity_sim/` and `scripts/`, and thresholds in `results/repo_analysis/problem_statement.md`.

Severity scale:
- **Critical**: blocks scientifically credible phase-3/4/5 outcomes.
- **High**: likely invalidates comparison quality or reproducibility if not fixed.
- **Medium**: does not fully block progress, but weakens claims and auditability.

## Ranked gaps

| Rank | Gap | Severity | Baseline evidence | Explicit downstream rubric mapping (phase 3/4/5) | What to fix next |
| ---: | --- | --- | --- | --- | --- |
| 1 | Conservation fidelity is failing by orders of magnitude on the current N-sweep baseline. | **Critical** | `results/baseline/metrics.md` reports energy drift `25422.63%` (N=16), `2338.06%` (N=64), `3945.65%` (N=256); angular momentum drift `214.91%` to `3792.85%`. Thresholds in `results/repo_analysis/problem_statement.md` are `<=0.10%` (energy) and `<=0.01%` (angular momentum). | **Phase 3:** `item_012` (symplectic comparison becomes trivial/uninformative if baseline is catastrophically unstable). **Phase 4:** `item_016`, `item_019` (protocol + threshold pass/fail impossible to interpret). **Phase 5:** `item_021` (claims lose credibility). | Calibrate stable baseline regime first (dt/softening sweeps by scenario), then lock a reference configuration that does not immediately violate conservation by 10^4-10^5x. |
| 2 | Metric contract is mismatched with project success definitions. | **Critical** | `scripts/collect_baseline_metrics.py` computes drift from final frame only (`energy_drift_pct`, `angular_momentum_drift_pct`) and reports mean step time, while success criteria require max-over-time drift and median runtime; orbit error is absent from baseline outputs. | **Phase 3:** `item_012` (energy-drift comparison should use consistent definitions). **Phase 4:** `item_016`, `item_019` (protocol + statistics depend on metric correctness). **Phase 5:** `item_021` (evidence-backed claims require metric parity with item_002). | Build one shared metric library: max drift over trajectory, two-body orbit RMS error, median step time, and explicit threshold pass/fail flags; make all phases consume the same functions. |
| 3 | Scenario coverage is incomplete for downstream method selection and evaluation. | **High** | Baseline metrics pipeline currently evaluates random N-body only (`run_case` uses `random_n_body`; outputs for N={16,64,256}); no analytic two-body/chaotic three-body track in metrics; no N>=512 baseline reference for scaling studies. | **Phase 3:** `item_011`, `item_012`, `item_013` (method choice and improvement claims need multi-scenario evidence and high-N baseline). **Phase 4:** `item_016`, `item_017`, `item_018` (experiment matrix and prior-work alignment need scenario completeness). | Expand baseline harness to scenario matrix: two-body analytic, three-body chaotic, random N-body; include N>=512 for scalability baseline and error-vs-speed curves. |
| 4 | Statistical power is insufficient (single-seed reporting). | **High** | `scripts/collect_baseline_metrics.py` runs one seed (`42`) per N; no confidence intervals/effect sizes; hash checks only confirm deterministic replay, not variability across seeds. | **Phase 3:** `item_012` (requires robust median improvements). **Phase 4:** `item_017`, `item_019` (>=5 seeds and CI/effect sizes are explicit). **Phase 5:** `item_021` (claims need uncertainty bounds). | Move to seeded batches (>=5 seeds per method-scenario pair), store per-run metrics, and aggregate with CI/effect-size outputs from the start. |
| 5 | Reproducibility manifest is not yet at audit-grade detail. | **High** | `results/baseline/hash_check.json` captures hashes only; no per-run manifest with full command, runtime environment, and commit hash linked to each raw output as required later. | **Phase 4:** `item_017`, `item_020` (controlled execution + independent audit). **Phase 5:** `item_022` (reproducibility package). | Emit `run_manifest.jsonl` for every run: command, seed, method, scenario, dt, softening, git commit, python/platform, timestamp, artifact path, artifact hash. |
| 6 | Performance measurements are confounded by instrumentation and process-level noise. | **Medium** | Memory usage is identical (`845.105 MB`) across all N in `results/baseline/metrics.md`, indicating poor discriminative signal; runtime includes full trajectory retention (`snapshot_every=1`) and diagnostics overhead, not isolated integrator throughput. | **Phase 3:** `item_013` (speed/accuracy tradeoff quality). **Phase 4:** `item_017`, `item_019` (controlled runtime comparisons). **Phase 5:** `item_021` (performance claims). | Split compute benchmark from artifact logging, use controlled snapshot cadence, and measure per-run peak RSS in isolated subprocesses. |
| 7 | Advanced-method evaluation harness is incomplete (despite partial implementation). | **Medium** | Symplectic stepping exists in `src/gravity_sim/simulator.py` and CLI exposes `--method symplectic`, but there is no shared evaluation artifact for baseline vs symplectic, and no scalable-force implementation/eval outputs yet. | **Phase 3:** `item_011`, `item_012`, `item_013`, `item_015`. **Phase 4:** `item_016`, `item_017` (method matrix execution). **Phase 5:** `item_021` (multi-method findings). | Create one evaluator pipeline that runs all methods over identical seeds/scenarios and writes comparable JSON for drift, runtime, and error-speed tradeoff plots. |

## Priority fix sequence (what to do next)

1. **Repair metric contract first** (Gap 2) so every subsequent result is definition-consistent with item_002 thresholds.
2. **Stabilize baseline operating point** (Gap 1) with documented dt/softening sweeps before any "improvement" claims.
3. **Upgrade protocol coverage and seed count** (Gaps 3-4) to match upcoming phase-4 matrix requirements.
4. **Add audit-grade run manifests** (Gap 5) before large experiment batches to avoid re-running due to provenance holes.
5. **Refactor benchmarking isolation + multi-method evaluator** (Gaps 6-7) to support credible phase-3 comparisons and phase-5 claims.
